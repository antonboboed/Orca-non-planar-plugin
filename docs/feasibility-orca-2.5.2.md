# Неплоская печать верхних поверхностей в OrcaSlicer 2.5.2: проверка возможности

Статус: **предварительная техническая проверка**. Полного переноса функции через плагин пока нет,
и этот документ не утверждает обратное.

## Что изучено

| Источник | Что это |
|---|---|
| [fich-l/orcaslicer-nonplanar](https://github.com/fich-l/orcaslicer-nonplanar) @ `74ef09f` | Сборка OrcaSlicer **2.4.2** с патчем `orca-nonplanar.patch` (≈5900 строк, 40 файлов) |
| `SoftFever/OrcaSlicer` тег `v2.5.2` (`f92a7c06`) | Исходники базовой версии 2.5.2 |

## Что делает референс

Референс — это **не плагин, а патч ядра слайсера**. Он меняет:

- `Print`/`PrintObjectSlice`/`Surface`/`LayerRegion`: выделяет верхние поверхности с уклоном ≤ 12° и
  высотой ≤ 5 мм, строит для них неплоские слои;
- `NonplanarSchedule`/`NonplanarSurface`: планирует порядок печати, чтобы сопло не задевало уже
  напечатанный материал;
- `NonplanarClearanceModel`: геометрия хотэнда (кончик Ø1.1 мм, конус, блок), которая проверяется по
  каждому перемещению;
- `GCode.cpp`/`GCodeWriter`: выводит движения с Z по точкам траектории;
- GUI (`Tab.cpp`, `ConfigManipulation.cpp`, `PrintConfig.cpp`): новые настройки
  `nonplanar_layers_angle`, `nonplanar_layers_height` и т. д.

Модель хотэнда в патче явно названа «упрощённой моделью A1 mini» и откалибрована по конкретному
принтеру. Для P1S она не подтверждена.

## Что даёт плагинный API 2.5.2

Плагины в 2.5.2 — это Python-скрипты с **capability** типа `SlicingPipeline`
(`src/slic3r/plugin/pluginTypes/slicingPipeline/`). Хуки вызываются из `Print::process()` и из
экспорта G-code.

| Возможность | Есть? | Комментарий |
|---|---|---|
| Читать срезы, поверхности, периметры, заполнение | да | `LayerRegion.slices`, `fill_surfaces`, `perimeters` |
| Менять 2D-геометрию поверхностей на шагах `posSlice`, `posPerimeters` и др. | да | `SurfaceCollection.set()`, `ExPolygon` |
| Задавать или менять **Z точек** экструзионных путей | **нет** | `ExtrusionPath.points()` возвращает read-only numpy-вид |
| Менять генерацию G-code (`GCode.cpp`) | **нет** | хука нет |
| Менять ConfigOption / UI для нового параметра | **нет** (через плагин) | только через `orca.host.ui`, и его нельзя вызывать из слайсинг-хука |
| Править готовый G-code после экспорта | **да** | шаг `psGCodePostProcess`, файл `ctx.gcode_path` правится на месте |
| Геометрия модели внутри `psGCodePostProcess` | **нет** | в контексте есть только путь к G-code и конфиг |

### Вывод по плагину

1. **Полноценная неплоская печать как плагин в 2.5.2 невозможна**: плагин не может задать Z точек
   траектории, а без этого неплоские слои не выводятся.
2. Единственный файловый хук — `psGCodePostProcess`. Через него можно переписать Z в готовом G-code,
   но:
   - нет геометрии и нет данных о поверхностях, их пришлось бы заново восстанавливать;
   - нет планирования порядка печати и проверки столкновений на этапе слайсинга, то есть то, что
     референс считает обязательным для безопасности;
   - такой путь **не рекомендуется** для печати без отдельной проверки.
3. **Реалистичный путь** — патч ядра (как у референса), перенесённый на 2.5.2. Это форк OrcaSlicer,
   а не плагин. Объём: портирование 5900 строк патча на другой код, сборка под Windows (Visual Studio,
   зависимости), длительная проверка на принтере. Я не могу собрать Windows-версию в этой песочнице.
4. **Гибрид**: плагин в роли независимой проверки G-code (`psGCodePostProcess`) — он не меняет
   траекторию, а проверяет её и останавливает экспорт/предупреждает при нарушении. Это законный
   способ использовать плагинный API. Прототип проверки уже есть: `tools/nonplanar-gcode-check/`.

## Что сделано в репозитории

- `tools/nonplanar-gcode-check/gcode_check.py` — независимая проверка G-code (только стандартная
  библиотека Python):
  - уклон каждого движения ≤ 12° (с настраиваемым лимитом);
  - диапазон Z, отрицательный Z, дуги G2/G3 и G28 (предупреждения);
  - экструзия при изменении Z (учитывается, не является ошибкой);
  - столкновение сопла с уже напечатанным материалом по **кончику и конусу** модели хотэнда из референса.
- `tools/nonplanar-gcode-check/test_gcode_check.py` — 15 модульных тестов (`python3 -m unittest`).

### Чего проверка НЕ делает

- Блок и корпус хотэнда выше 2.5 мм над кончиком не моделируются. Если в таком месте есть материал,
  проверка выдаёт предупреждение `UNCHECKED_HIGH`, а не молча пропускает движение.
- Не проверяет реальный хотэнд P1S, моторы, инерцию, деформацию стола.
- Не планирует порядок печати. Если референс нашёл бы допустимый порядок, а этот инструмент получил бы
  уже готовый G-code, то он только проверит столкновения в данном порядке.
- **Чистый отчёт — это не сертификат безопасности.** Печатать первые тесты нужно с контролем.

## Ограничения для P1S (сопло 0,4 мм)

- Референс проверен на A1 mini; по сообществу P1S «работает» при 12° и 5 мм, но это не
  инженерная проверка для вашего экземпляра принтера.
- Тестовый файл `111.3mf` с Google Drive из песочницы не скачивается (сервер отвечает HTTP 500,
  соединение с `drive.google.com` не проходит). Нужна загрузка файла в рабочую папку вручную.

## Открытые вопросы

1. Выбор пути: **форк ядра** (как референс, полная функция, нужна сборка под Windows) или
   **плагин-проверка** (безопасно, но сама неплоская траектория не появится).
2. Будет ли достаточно теста на `angle-test-v1.3-A.stl` из референса, если `111.3mf` не загрузится.
